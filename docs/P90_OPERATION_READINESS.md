# 软游部落 P9.0 正式商业运营准备与日常运维 SOP 手册

## 一、P9.0 运营阶段目标

在七大核心主导航频道 UI 3.0 收官与 P8.9 全站生产级体检完成后，软游部落（SoftTribe）已具备迈向 **P9.0 正式常态化运营** 的技术基础。本手册旨在规范日常内容采编、版本更新、下载来源巡检、异常监控告警与灾备策略，保障平台长期合规、高可用与可信运营。

---

## 二、日常内容生产与审核 SOP

### 1. 软件/工具入库标准流程
1. **来源可信度初审**：
   - 优先收录软件著作权人官方主站发布的原始安装程序或开源官方代码托管平台（GitHub/GitLab）。
   - 严禁录入带有捆绑流氓推广、修改版或未知篡改脚本的第三方下载器链接。
2. **状态机控制**：
   - 新录入资源初始状态必须设为 `DRAFT` 或 `PENDING_REVIEW`。
   - 必须由审核员（`REVIEWER`）或管理员（`ADMIN`）二次确认无误后，方可将其变更状态为 `PUBLISHED`。
3. **元数据录入规范**：
   - 软件全称、英文名、适用平台（Windows 11/10/7）、架构（x64/x86/arm64）。
   - 开发者官方网址、开源许可证（MIT/GPL/Apache/商业免费）。
   - 官方图标与真实软件界面截图。

### 2. 软件实操教程编写规范
1. **结构化技术要求**：
   - 必须包含：问题背景、适用系统、前置准备清单（Preflight Checklist）、高危操作警示横幅（Risk Banner）、分步操作实录、相关官方软件关联卡片。
   - 正文二级标题（`## `）与三级标题（`### `）规范化命名，以便系统自动提取动态目录导航（TOC）。
2. **高风险操作免责声明**：
   - 凡涉及 BIOS/UEFI 固件刷新、磁盘分区调整、系统注册表修改与原版系统重装的教程，必须强制标注高风险警告并提醒“操作前请备份所有个人重要数据至移动硬盘或云端”。

## 三、软件版本监测与时间线维护 SOP

### 1. 发版日期口径规范（严禁混淆）
- `releaseDate`：必须严格依据软件开发者或官方发布的实际发版日期（如官网 Release Notes 标注时间）。
- `catalogedAt` / `updatedAt`：本站收录入库或编辑修改的时间。
- **红线**：严禁将本站后台编辑日期伪造为软件最新发版日期。

### 2. 更新日志真实性原则
- 仅展示官方明确公布的变更记录（Changelog）。
- 若官方未提供更新日志，标注为“官方暂未提供本次版本详细更新日志”，严禁通过 AI 编造虚假安全修复或漏洞 CVE 编号。

## 四、下载渠道健康巡检与分级治理 SOP

### 1. 每周自动巡检任务
- 依托系统内置后台作业服务（`server/src/modules/jobs/`），每周定期对全站 `DownloadSource` 发起轻量 HTTP HEAD 探活。
- 若连续两次检测返回 `404` 或超时，系统自动将来源状态变更为 `UNAVAILABLE` 并触发后台通知。

### 2. SHA-256 原厂指纹补齐行动
- 在 P9.0 运营期间，运营组应针对 Top 30 核心装机软件逐步从官方来源下载安装包，通过 `Get-FileHash` 计算权威 SHA-256 指纹录入数据库，使下载来源逐步由 Level 3/4 真实升级至 Level 5。

## 五、系统稳定性监控与告警阈值

| 监控维度 | 采集指标 | 正常基准 | 预警阈值 | 应急处理动作 |
| :--- | :--- | :---: | :---: | :--- |
| **服务器磁盘** | 根分区 `/dev/vda2` 使用率 | <= 80% | **>= 90%** | 执行备份归档清理脚本，释放临时缓存 |
| **进程守护** | PM2 `softtribe-backend` 状态 | `online` | 进程重启或 `errored` | 查看 `pm2 logs`，排查内存泄漏或崩溃 |
| **内存使用** | 系统物理空闲内存 | >= 1.5GB | **< 300MB** | 重载内存占用过高子进程，释放缓存池 |
| **Web 服务** | Nginx HTTP 状态码分布 | 2xx/3xx > 99% | **5xx 激增** | 检查 Fastify 3008 端口反代连接与连接池 |
| **SSL 证书** | Let's Encrypt 证书有效天数 | 88 天 | **< 15 天** | 触发 `certbot renew` 自动化续签指令 |

## 六、数据库灾难恢复与异地冷备 SOP

### 1. 定时备份配置核查
- 每天凌晨 03:00 自动生成压缩格式 dump 文件并存放于 `/home/ubuntu/backups/softtribe/`。
- 本地保留周期：14 天滚动清理。

### 2. 季度灾难恢复演练 SOP
1. 搭建隔离测试数据库实例（非生产库）。
2. 从最新 dump 文件执行恢复：
   ```bash
   pg_restore -U softbuluo -h 127.0.0.1 -d softbuluo_drill -F c /path/to/backup.dump
   ```
3. 抽样核验用户表、软件表、教程表记录完整性与外键约束。
4. 记录演练耗时与恢复报告，持续确保备份文件真实具备可恢复性。
